self-taught  ·  9×9 Go

Four thousand years of Go. Four thousand lines of Go.

Gofer is an AlphaZero-style Go engine — a bitset board, PUCT search, batched ONNX inference and GTP, in Go — plus a PyTorch loop that taught it 9×9 Go from random play. 3.6 hours on four CPU cores later, it beats GNU Go 66–34. Every number on this page is measured: Wilson intervals, an Elo ladder, GNU Go as the yardstick.

Inside the engine

Everything a Go engine needs. Nothing it doesn't.

One binary plays, analyzes, referees and generates training data; Python only trains. The design is written down in docs/architecture.md.

Rules that hold up

Chains and exact liberties kept incrementally in bitsets, simple ko, positional superko from per-chain Zobrist hashes, Tromp-Taylor area scoring. Differential-tested against a naive reference on random games from 5×5 to 19×19.

internal/game · 0.7 µs per move incl. legal moves

PUCT search, done right

One documented sign convention, virtual-loss leaf batching, Dirichlet root noise, tree reuse, exact scoring of finished games, and a pass rule that keeps an untrained net from ending games at random.

internal/mcts · regression test for every v2 defect

Batched inference

Concurrent searches feed one evaluator; worker sessions run ONNX Runtime on every CPU core, or CUDA / TensorRT on a GPU. Random board symmetry per evaluation and a position cache.

-device cpu|cuda|tensorrt · 6×64 net · 477k params

Speaks GTP

Drop it into Sabaki or Lizzie. Live lz-analyze overlays, time_settings/time_left budgets, undo, final_score, resignation.

bin/gofer gtp -model models/gofer-9x9.onnx

A data factory

Self-play with KataGo's playout-cap randomization writes compact NumPy shards: 13 feature planes, visit-count policy, game result, search value, final ownership. Resignation with measured false-positive rate.

gofer selfplay → .npz · ~1.2 games/s on 4 vCPUs

An honest arena

Any two players — networks, rollout MCTS, GNU Go or any GTP engine. Paired openings with colors swapped, GNU Go dead-stone adjudication, Wilson intervals, Elo, and SPRT for gating.

gofer arena -a nn:model.onnx -b gnugo,level=10

The training loop

Random play to GNU Go, in an afternoon.

Every generation: the newest network plays itself, a replay window of recent games trains the next one with all eight board symmetries, the export is checked against PyTorch, and the result is rated against its predecessor and against GNU Go. Stop it anywhere — the same command resumes.

No gate

Like AlphaZero and KataGo, the newest network always plays the next games. Evaluation is measurement, not a toll booth — v2 spent five times more compute gating than generating data. SPRT is there if you want a gate.

The yardstick

Strength is measured against an engine nobody tuned for: GNU Go 3.8 — 66–34 at its default level 10, 78–22 at level 1, over 100 games each with colors swapped. GNU Go judges dead stones at the end of every game.

The honest part

v2's search backed values up with the wrong sign and skipped the search on fresh trees, so its training never had a chance. The audit lists every defect, with measurements and a regression test.

Where the time goes

      
The network is the only bottleneck.

      
v2 spent about as long in Go code as in the network for every evaluation, and ran the network on one core. v3 keeps chains and liberties incrementally, so a whole search step costs ~4 µs, and spreads inference over every core — or a GPU.

      
Measured on a 4-vCPU cloud VM with go test -bench and gofer bench.

Paper trail

  
Every defect, written down.

  
v3 started with an audit of v2. The findings, the design that replaced it, and the run that proved it are all in the repo — including v2's original decision records.


  

    
      AUDIT
      Why v2 could not learn
      Inverted backup sign, searches that never ran, near-uniform policy targets, one-core inference, truncated games — 13 defects, each measured.
      
    
    
      DESIGN
      Architecture
      Packages, the search's sign convention, batching, feature schema, network and data format.
      
    
    
      TRAIN
      Training guide
      The loop, its settings, throughput by network size, and how to run it on a GPU.
      
    
    
      RESULTS
      The run
      Every generation: self-play speed, held-out losses, Elo, and results against GNU Go.
      
    
    
      ADR
      v2 decision records
      The original five ADRs, kept for the record.
